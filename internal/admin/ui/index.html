新建任务

一个任务 = 一份调度 + 一个 handler 名字。在有执行器注册了这个 handler key 之前，它不会被任何东西执行。

标识
租户内唯一。日志、审计记录和 execution key 里都用这个名字标识它。
必须与某个执行器声明的 key 完全一致。对不上的话，任务会正常生成执行记录，但永远不会被派发出去。
调度
CRON：每个触发时刻生成一条执行记录，所以漏掉一次就是真的少跑一次。FIXED_DELAY：同时只跑一轮，上一轮结束后再等固定时长开下一轮。
停机期间错过的触发时刻怎么处理。FIRE_ONCE：补跑一次。SKIP：直接跳到下一个未来时刻，一次都不补——五分钟的故障会让日任务整天不跑。
关掉后配置和调度都还在，但不会被领取执行。迁移时先建好、验证过，再切过来。
路由与并发
留空表示任何提供该 handler 的执行器都可以。填了组名就只发给那个组 ——灰度就是这么做的：金丝雀只吃自己那一份，不碰生产的。
QUEUE：新一轮到点了就排队，等正在跑的那轮结束。FORBID：直接跳过，并记为 skipped。
限额
单次 attempt的运行上限，从领取那一刻开始计时。超时是终态，不会重试——把整个预算跑光的一轮，重试大概率还是跑光。
本调度器多久不续租，别的实例就可以接管这份工作。最小 10 秒，且不能超过 timeout。没有明确理由就别动它。
每次触发最多尝试几次（含第一次）。如果失败的 failure_kind 以permanent开头，会提前停止，不再浪费剩余次数。
另一份独立预算，用于调度器崩了或执行器失联导致「不知道到底跑没跑」的那些 attempt。花掉它不占用上面的重试次数。
参数
传给 handler 的 JSON 对象。手工触发时填的参数是合并覆盖在这份之上，不是整体替换。不要放密钥——它存在租户库里、显示在这个页面上、还会经网络传给执行器。
